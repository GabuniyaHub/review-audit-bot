# review-audit-bot

Учебный прототип ВКР: Telegram-бот для сравнительного репутационного аудита своей компании и трёх конкурентов по отзывам из 2ГИС и Яндекс.Карт.

Планируемый стек: NestJS, TypeScript, PostgreSQL, Telegram Bot API, LLM API. Сбор отзывов отделён от анализа; частоты и показатели рассчитывает приложение.

## Текущее состояние
Этап 1 завершён: подготовлены требования, выбран пилот в Тюмени, исследованы сборщики и проверена живая постраничная выгрузка обоих источников. Из 2ГИС отобраны 500 отзывов; по Яндексу проверены 415 отзывов трёх карточек и отклонено включение 50 отзывов несопоставленного филиала «Максима». Сопоставление адресов Брюта также требует окончательного подтверждения. Этап 2: основа NestJS/PostgreSQL реализована. Этап 3: Telegram-команды и пошаговая настройка реализованы; живое подключение требует токена. Этап 4: реализованы очередь сбора, адаптеры, нормализация и хранение; Яндекс проверен вживую, 2ГИС — на записанных ответах, свежая сетевая проверка требует разрешённого ключа. Анализ LLM ещё не подключён.

## Локальный запуск

Требуются Node.js 22–26 и доступный PostgreSQL (интеграционные тесты используют собственный PostgreSQL 18).

```bash
npm ci
cp .env.example .env
```

Создайте отдельные роль и базу PostgreSQL. Например, на Ubuntu с установленным PostgreSQL:

```bash
sudo -u postgres createuser --pwprompt review_audit
sudo -u postgres createdb --owner review_audit review_audit
```

Укажите имя базы, пользователя и пароль в DATABASE_URL файла .env. Специальные символы пароля нужно URL-кодировать. Затем:

```bash
npm run db:migrate
npm start
```

Проверки: `/health/live` и `/health/ready` на `http://127.0.0.1:3000`. До миграции readiness вернёт 503. Если база недоступна, HTTP остаётся доступен для диагностики, readiness возвращает 503.

```bash
npm test
npm run test:integration
```

Интеграционные тесты не требуют вашей рабочей базы. Запускайте их обычным пользователем, не root. Режим разработки: `npm run start:dev`.

## Собранное приложение

```bash
npm ci
npm run build
npm prune --omit=dev
npm run db:migrate:prod
npm run start:prod
```

`npm run db:migrate` и сборка требуют dev-зависимостей; после их удаления используйте `db:migrate:prod`. Секреты задаются через окружение или локальный .env; миграции выполняются отдельно от старта сервиса. Приложение размещено на сервере; точное состояние LLM описано в инструкции этапа 5.

## Telegram

После применения миграций укажите в локальном .env `TELEGRAM_ENABLED=true` и `TELEGRAM_BOT_TOKEN` своего бота. Запустите приложение и напишите боту `/start`. По умолчанию Telegram отключён; тесты не требуют токена и не отправляют реальные сообщения.

Начать настройку: `/setup`; применить после заполнения: `/save`; отменить черновик: `/cancel`. `/sources` показывает карточки, `/confirm ID` подтверждает нужный филиал, `/collect` запускает сбор при COLLECTION_ENABLED=true. Для 2ГИС доступен TWOGIS_MODE=browser (CAPTCHA может остановить сбор) либо api с разрешённым TWOGIS_REVIEWS_KEY. `/report` формирует сводку и Markdown-файл по текущим анализам; /analyze ставит анализ в очередь при ANALYSIS_ENABLED=true. Подробности — в инструкции этапа 3.
