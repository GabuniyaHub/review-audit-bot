# Этап 2: основа приложения

Дата: 16.10.2026.

## Реализовано
NestJS 12, TypeScript, ESM, драйвер PostgreSQL `pg`. ORM не используется: исходная схема и ограничения видны в SQL миграции. Девять таблиц предметной области: пользователи, проекты аудита, организации, карточки источников, запуски сбора, отзывы, версии анализа, аудиты и отчёты.

Конфигурация проверяется перед запуском; сообщения об ошибках не содержат значения секретов. Приложение по умолчанию слушает только 127.0.0.1:3000. Telegram и LLM не подключены на этом этапе, токены для запуска основы не требуются.

## PostgreSQL и миграции
`src/database/migrations.ts` — версионированный SQL и SHA-256 контрольная сумма. `npm run db:migrate` собирает и применяет миграции. Для уже собранного приложения без dev-зависимостей: `npm run db:migrate:prod`.

Применение — в транзакции с advisory lock. Повторный и одновременный запуск не применяют одну миграцию дважды. Изменение уже применённой миграции отклоняется. Схема не синхронизируется автоматически при старте приложения. Для изменений добавлять новые версии; автоматического разрушительного отката нет.

Схема запрещает повтор одного отзыва в карточке, несколько активных аудитов одного проекта, несколько активных сборов одной карточки и связи дочерних объектов с чужим проектом. Один основной филиал на проект ограничен уникальным индексом. Ограничение трёх конкурентов и проверка принадлежности проекта Telegram-пользователю будут реализованы в сервисах этапа 3; одной схемы для авторизации недостаточно.

Дата публикации и дата обновления источника разделены. Отдельно хранятся ID отзыва, ключ дедупликации, хеш текста, версия модели/промпта/схемы. Сведения о несопоставленных филиалах не считаются подтверждёнными автоматически.

## Проверка состояния
- `GET /health/live`: приложение отвечает, независимо от доступности базы.
- `GET /health/ready`: 200 только при доступной базе с ожидаемой историей миграций; иначе 503.

Пул ограничен пятью соединениями по умолчанию, есть тайм-ауты подключения и запросов. SIGTERM/SIGINT закрывают HTTP и пул. API ошибок не возвращает стек, текст SQL, пароль базы и query-параметры запроса. Сырые ошибки подключения и тела запросов не журналируются. При DB_SSL=true проверка сертификата обязательна; SSL-параметры в DATABASE_URL отвергаются, чтобы не переопределить эту настройку.

## Проверки
`npm test`: три проверки конфигурации.
`npm run test:integration`: семь сценариев в одной группе против отдельного временного PostgreSQL 18: неподготовленная база, миграции и повторный/конкурентный запуск, ограничения уникальности и связей, контрольная сумма, отсутствие секретов в HTTP-ошибках, запуск обычной точки входа и SIGTERM, потеря базы.

Интеграционные тесты создают собственный кластер на свободном локальном порту, не используют DATABASE_URL из .env и удаляют временные данные после завершения. Бинарники поставляются dev-зависимостью embedded-postgres из npm. Установка требует разрешённых postinstall-скриптов. PostgreSQL не должен запускаться от root; тесты рассчитаны на обычного пользователя. Поддержка конкретной ОС/архитектуры зависит от пакета бинарников.

Проверено локально на macOS arm64, Node.js 26.8.2, PostgreSQL 18.4. Боевая установка и проверка на PostgreSQL 16 ещё не проводились. Действующий сервер с двумя сайтами не изменялся.
