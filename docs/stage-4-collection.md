# Этап 4: сбор, нормализация и хранение отзывов

Дата: 16.10.2026.

## Реализовано
Собственные TypeScript-адаптеры 2ГИС и Яндекс.Карт, ограниченная постраничная загрузка без браузера, сохранение в PostgreSQL, повторный сбор и обновление существующих записей. Сбор и анализ разделены: LLM на этом этапе не вызывается, итоговый репутационный отчёт не генерируется.

### Telegram
1. `/sources` — посмотреть карточки с названием и адресом филиала.
2. Открыть ссылки и проверить соответствие филиалов.
3. `/confirm ID` — явно подтвердить каждую нужную карточку своего проекта.
4. `/collect` — поставить в очередь только подтверждённые и подключённые карточки.
5. `/status` — результат последнего сбора по каждой карточке, количество обработанных отзывов, лимит или ошибка.

Повтор `/collect` не добавляет второе активное задание на ту же карточку. Чужую карточку подтвердить нельзя. Если ключ 2ГИС не задан, соответствующие карточки пропускаются с сообщением о неподключённом источнике; Яндекс может работать самостоятельно. По завершении задания в Telegram-очередь записывается уведомление с результатом или причиной ошибки. Подтверждение пользователем не является автоматической проверкой адреса: оно явно учитывает ограничения сопоставления, найденные на этапе 1.

## Настройки
```
COLLECTION_ENABLED=true
COLLECTION_MAX_REVIEWS=150
COLLECTION_TIMEOUT_MS=15000
COLLECTION_PAGE_DELAY_MS=1000
TWOGIS_REVIEWS_KEY=
```
Сбор по умолчанию отключён. Максимальный лимит — 1000 записей на карточку; штатный — 150. Ограничение относится к выборке, а не обещанию выгрузить все отзывы. Токен Telegram и ключ интерфейса отзывов 2ГИС задаются отдельно. Обычный ключ Places API не считается подтверждённым доступом к текстам отзывов.

## Источники
### Яндекс.Карты
Загрузка публичного HTML карточки по числовому ID, `page` и `sort_by=by_time`; разбор `script.state-view` через Cheerio. Карточка ищется по точному ID, чужой businessId в отзыве отклоняется. Доступность такого HTML не является гарантией стабильности интерфейса. CAPTCHA и изменение структуры — отдельные ошибки, без автоматического обхода.

`updatedTime` хранится как дата обновления. Дата публикации остаётся неизвестной, если не получена отдельно: нельзя применять к ней фильтр периода как к достоверной дате создания. Названия и адреса площадки здесь не используются для автоматического изменения пользовательских настроек.

### 2ГИС
Метод интерфейса отзывов, исследованный в `ruvn-1fgas/2gis-parser` (кандидат согласован для некоммерческого ВКР), с limit/offset и сортировкой date_created. Сам Scrapy-проект и его код в приложение не копировались; браузер и Python на сервере не требуются. Встроенный ключ стороннего репозитория в код, Git и .env.example не перенесён.

Проверка нового сетевого запроса с извлечением ключа стороннего репозитория была отклонена автоматической проверкой безопасности из-за неподтверждённого права использования. Запрос не выполнялся. Для свежей живой проверки требуется разрешённый ключ с доступом к интерфейсу отзывов. Офлайн-проверка сохранённых ответов не доказывает работоспособность новой HTTP-сортировки или доступа с новым ключом.

## Данные и ограничения
- Очистка Unicode NFC, пробелов, переносов и нулевого символа; текст и смысл не переписываются.
- Рейтинг проверяется в диапазоне 1–5, отсутствие оценки допустимо. Можно сохранить оценку без текста; последующий смысловой анализ должен исключать пустые тексты.
- При наличии ID: уникальность карточка + ID; отредактированный текст и рейтинг обновляют ту же запись.
- При отсутствии ID: детерминированный отпечаток текста, оценки, доступной даты и ключа автора. Правку отзыва без ID невозможно надёжно связать с предыдущей версией; возможна новая запись. Ключ автора не сохраняется открытым текстом.
- Хеш содержимого меняется при изменении текста/оценки; прежние результаты анализа сохраняются как история, а актуальный анализ должен соединяться по этому хешу.
- Совпавшие нормализованные тексты разных площадок не удаляются: сохраняется text_fingerprint для будущего сопоставления.
- Неизвестные/невалидные даты остаются NULL, исходная строка сохраняется. Смена дня из-за часового пояса учитывается корректно.
- Отдельная ссылка на отзыв хранится только если площадка её вернула; URL карточки не выдаётся за точную ссылку на отзыв.
- Неудачный/частичный сбор не удаляет старые отзывы. Удаление отзыва с площадки не выводится из отсутствия в ограниченной выборке.
- Достижение лимита отмечается как partial со stop_reason=limit. Короткая последняя страница означает exhausted только в рамках ответа площадки; это не гарантия отсутствия скрытых/недоступных отзывов.

## Очередь и восстановление
Миграция `003_collection`; прежние миграции не изменены. Задания хранятся в БД, захватываются с `FOR UPDATE SKIP LOCKED`, имеют отдельный worker_token и возобновляемую пятиминутную аренду. Страница отзывов и её счётчики сохраняются одной транзакцией; токен защищает запись от запоздавшего исполнителя после повторного захвата. Истёкшая аренда подхватывается заново, а после трёх попыток фиксируется terminal failure. Повторная страница не увеличивает счётчик уникальных отзывов задания.

Повторы ограничены тремя попытками для timeout/unavailable/rate_limited, с задержкой и учётом Retry-After. CAPTCHA, неверный формат, запрет доступа и отсутствие настройки — терминальные ошибки. Если часть страниц уже сохранена, итог — partial с причиной сбоя. Сетевые запросы имеют тайм-аут, до трёх переходов и лимит тела 5 МБ; редирект на посторонний домен/локальный IP отклоняется. Тексты отзывов, ключи и сырые ошибки сети в журналы не выводятся.

Обработчик очереди запускается с приложением при COLLECTION_ENABLED=true. Это выполнение явно поставленных задач; ежедневный запуск по расписанию относится к этапу 7. Один процесс обрабатывает по одному заданию. Несколько процессов могут разбирать разные карточки; глобальный лимит запросов на источник между серверами пока не реализован.

## Проверки и фактические результаты
- 15 модульных проверок: ссылки, нормализация, даты, ID, редиректы, CAPTCHA, 429, размер ответа, повтор страниц и корректная маркировка лимита.
- 10 интеграционных сценариев на отдельном настоящем PostgreSQL, включая прежние этапы: принадлежность подтверждения, отсутствие дублей, обновление текста, сохранение данных при CAPTCHA, уведомления, ограниченные повторы, восстановление истёкшего задания и terminal failure.
- Живой Яндекс → адаптер → PostgreSQL: Garden 125 отзывов (лимит) + Optimist 115 (короткая последняя страница). Всего 240; повтор Garden оставил общее число 240.
- Записанные ранее ответы 2ГИС → подставной HTTP → тот же адаптер → PostgreSQL: 4 × 125 = 500 отзывов; повтор сохранил число 500. Новых внешних запросов и использования API-ключа в этом тесте не было. Завершение страниц этого теста относится только к предоставленным записям, не всей площадке.

Протоколы: `live-yandex-stage4-results.json` и `recorded-2gis-stage4-results.json`; тексты, авторы и ключи в Git не добавлены. Проверки использовали временный PostgreSQL локально; общий PostgreSQL на сервере не изменялся.

## Воспроизводимость
```
npm ci
npm test
npm run test:integration
```
Живая проверка только Яндекса, без ключей и без Telegram:
```
npm run build
node tools/validate-live-collection.mjs live-yandex-results.json --yandex-only
```
Живая проверка обоих источников: сначала задать разрешённый TWOGIS_REVIEWS_KEY через окружение, затем запустить ту же команду без --yandex-only. Режим --recorded-2gis <каталог> использует локальные записанные ответы `<ID>-sample.json`; эти данные не входят в репозиторий. Все режимы создают и удаляют отдельный временный кластер PostgreSQL, рабочая DATABASE_URL не используется.

## Развёртывание
В этом этапе подготовлен и проверен код; текущая установка сервера с .env не обновлялась автоматически. Для обновления нужны новая сборка и рабочие зависимости, миграция 003, затем параметры COLLECTION_* и перезапуск службы. Для 2ГИС отдельно нужен разрешённый TWOGIS_REVIEWS_KEY. Текущий токен Telegram и пароль БД не заменять.
