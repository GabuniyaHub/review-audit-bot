# Этап 6 — сравнение и отчёт

Разработка и проверка выполняются на Mac. Сервер остаётся на этапе 5 с отключённым LLM из-за HTTP 403. На Mac уже подтверждены HTTP 200 и JSON-контракт реального Nemotron на двух вымышленных отзывах; это не оценка качества на корпусе.

## Пользовательский сценарий

1. Настроить свою компанию и до трёх конкурентов: /setup, /sources, /confirm ID.
2. /collect — собрать отзывы. CAPTCHA и недоступность источников остаются отдельными ограничениями.
3. /analyze — получить текущие проверенные анализы через доступный LLM endpoint.
4. /report — сформировать отчёт по всем сохранённым отзывам; /report 2026-10-01 2026-10-16 — задать одинаковый период для всех компаний, границы включительно, дни UTC.
5. Бот возвращает короткую подпись и файл audit-ID.md через Telegram sendDocument. Содержимое хранится в PostgreSQL; локальные пути и внешнее хранилище не требуются.

Генерация отчёта не вызывает LLM: численные показатели, сравнение и действия по фиксированным темам рассчитываются программой по уже сохранённым анализам. Это экономит запросы, повышает воспроизводимость и исключает выдуманные числа. Это набор правил, а не дополнительный генеративный анализ рекомендаций.

## Содержание и ограничения

- Своя компания и конкуренты, число отзывов/текстов/актуальных анализов/оценок, покрытие, средняя оценка именно выборки, распределение тональности.
- Частота темы: уникальные ID отзывов с темой / число текстовых отзывов с проверенным текущим анализом данной организации. Одна тема на отзыв учитывается один раз. Неанализированные тексты остаются в отдельном показателе покрытия.
- Раздельные положительные, отрицательные и смешанные упоминания. Для сравнения жалоб используются отрицательные + смешанные упоминания. Разница в процентных пунктах — описательная статистика, не доказательство значимости и не рейтинг.
- При менее 30 анализах у любой сравниваемой компании численные различия подавляются. Они также подавляются при наличии отзывов с неизвестной датой в выбранной выборке. Порог 30 — защитное правило интерфейса, не гарантия статистической достаточности.
- При заданном периоде неизвестные даты исключаются. Без периода они входят в общую выборку с предупреждением. Интерфейсная дата редактирования не подменяет публикацию.
- Источники, состояния последнего сбора, лимит выборки, неподтверждённые филиалы и ошибки видны в отчёте. Совпадения текста помечаются, а не удаляются автоматически.
- До пяти приоритетных действий по жалобам своей компании, в порядке числа оснований. Каждое связано с ID отзывов, точными цитатами из обезличенного текста и безопасными ссылками на источник/карточку. Если обоснованных тем меньше трёх, дополнительные проблемы не выдумываются.
- Чужие, устаревшие, несовместимые с моделью/версиями или невалидные анализы не используются. Отчёт с нулём актуальных анализов не создаётся. При частичном покрытии выдаётся partial с предупреждением.

## Хранение, повторные запросы и доставка

Миграция 005_reports добавляет отпечаток снимка входных данных и текст/имя вложения в telegram_outbox. Снимок компаний, источников, отзывов и текущих анализов считывается одним SQL-оператором; блокировка проекта и транзакция защищают создание отчёта. Повтор идентичного запроса возвращает тот же отчёт с прежней датой. Изменение входных данных, периода или версии отчёта создаёт новый снимок. Во время активного аудита предлагается дождаться его завершения.

Вложение и ответ сохраняются в той же транзакции, что и обработка Telegram-команды. Существующие повторы доставки действуют и на документы. Как обычно для внешнего API, при сбое между фактической отправкой и записью подтверждения возможна повторная доставка файла. Содержимое Markdown экранируется, ссылки допускаются только на источники 2gis.ru/yandex.ru/yandex.com.

## Локальная проверка

```
npm test
npm run test:integration
node tools/demo-report.mjs data/demo-report
```

Последняя команда требует ключ в приватном окружении. Она отправляет только восемь вымышленных текстов, использует реальную модель и пишет report.md, metrics.json и analysis.json с пометкой демонстрации. Не запускает Telegram и не затрагивает рабочую базу. Для диагностики допускается --server-key при заданном DEMO_SSH_KEY: существующий ключ OpenRouter читается через авторизованный SSH только в память процесса, без сохранения на Mac. Эта опция привязана к текущему тестовому серверу и не нужна обычному пользователю.

Тесты проверяют формулы и знаменатели, границы периода, неизвестные даты, цитаты, фильтрацию URL, multipart-вложения, кэш, изменение текста и изоляцию пользователей. В PostgreSQL используется временная локальная база. Демонстрационные данные и тесты не заменяют эксперимент ВКР на 500 реальных отзывах и ручную оценку качества модели.

## Фактические результаты 16.10.2026

- 28 модульных тестов и 13 проверок PostgreSQL прошли.
- Реальный запрос с Mac к Nemotron через OpenRouter: 8 из 8 вымышленных отзывов прошли JSON-валидацию, сформированы 3 рекомендации с проверенными цитатами. Запрос и сборка демонстрационного отчёта заняли 52.2 секунды; это не замер полного цикла со сбором реальных источников.
- [Пример отчёта](examples/stage-6-demo.md) помечен как демонстрация; источников реальных отзывов у него нет.
- Доставка Markdown проверена через тестовый Telegram API, реальные сообщения не отправлялись. Сервер и его база не обновлялись. Постоянный локальный Telegram-процесс не запускался, чтобы не конфликтовать с серверным poller.
- Проверка качества модели на реальном размеченном корпусе и ограничения сборщиков остаются открытыми задачами.
