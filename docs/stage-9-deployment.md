# Этап 9 — серверная установка

Целевая установка: /opt/review-audit-bot, служба review-audit-bot, пользователь review-audit, существующая PostgreSQL 16 с отдельной базой review_audit. Приложение слушает только 127.0.0.1:3001. Базы и службы двух сайтов не объединяются с ботом и не заменяются.

При обновлении создаются закрытые резервные копии БД, env и предыдущей сборки. Код берётся из main GitHub; приватный SSH-ключ остаётся на Mac, доступ GitHub передаётся временным SSH-agent. Сборка выполняется на Mac, на сервер передаются только dist/src. Секреты остаются в серверном .env и не включаются в репозиторий или журналы.

Миграции применяются отдельно от старта. Существующая systemd-служба обеспечивает перезапуск и ограничения ресурсов. После обновления проверяются версия, /health/live, /health/ready, Telegram getMe, состояние процессов и оба сайта. Рабочие Telegram-сообщения для диагностики не отправляются.

Разворачиваются настройка компаний, подтверждение карточек, сбор доступных источников, хранение отзывов/анализов, формирование и доставка отчётов, программный модуль расписания и инструменты эксперимента. Включение компонента определяется фактической проверкой доступа:

- LLM на сервере ранее возвращала HTTP 403 Access denied by security policy; пока нет успешного запроса, ANALYSIS_ENABLED=false.
- Без рабочего анализа SCHEDULER_ENABLED=false: полный ежедневный цикл нельзя выдавать за работающий.
- Браузерный 2ГИС ранее запрашивал CAPTCHA; Chromium удалён для освобождения диска. Режим api без ключа оставляет 2ГИС неподключённым; интерфейс сообщает об этом, не делает пустой успешный сбор.
- Яндекс проверяется отдельно живым запросом. COLLECTION_ENABLED включается только при успешной проверке.
- /report работает по существующим актуальным анализам. Если их нет, сообщает об отсутствии данных и предлагает /analyze; наличие команды не означает наличия готового реального аудита.

## Эксплуатация

```
systemctl status review-audit-bot
journalctl -u review-audit-bot --since today
curl http://127.0.0.1:3001/health/ready
```

Не выводить .env в терминал или чат. Перед обновлением БД сохранять pg_dump; восстановление выполнять согласованно с остановкой записи. Для возврата к старой сборке учитывать версию миграций: дополнительная миграция может сделать старый readiness несовместимым. Самовольный откат схемы не выполняется.

Для анализа через OpenRouter подтверждена работа с Mac. Постоянный локальный poller не запускается одновременно с серверным под одним токеном. Гибридная доставка анализов и перенос обработчика в другую разрешённую среду требуют отдельной настройки.

Полные фактические результаты текущего развёртывания фиксируются отдельно после живых проверок; неподтверждённые компоненты не объявляются рабочими.

Итог: доступная серверная часть развёрнута; полный автоматический аудит на сервере пока не работает из-за LLM/2ГИС и отсутствия готового корпуса анализов. Инструменты этапа 8 готовы, но реальные метрики качества и полный замер времени остаются незавершёнными. Следующая пользовательская проверка: /start → /setup → /sources → /confirm ID → /collect (для Яндекса), затем /status. Для реального анализа требуется Mac либо разрешённый доступный API в серверной среде.
